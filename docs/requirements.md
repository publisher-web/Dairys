# 要件定義（Step 2）— 案

状態: **ドラフト（2026-11-26）**。「選択肢」の各項目は、ユーザーが選んだら「決定」に書き換え、`decisions.md` に記録する。

## 0. 設計の原則（分析からの結論）

| # | 原則 | 根拠（`analysis-current-state.md`） |
|---|---|---|
| P1 | **その場の入力は1画面・10秒以内**。必須項目は「何か1つ」だけ | 旧運用は1件に15～20操作＋YAML 7項目で途絶えた |
| P2 | **入口は1つ**。日記・出来事・支出を書き分けさせない | 入口が5系統に分かれていた |
| P3 | **手打ちさせない**。時刻・天気は自動、人物・場所は候補から選ぶ | `[[姓 名\|呼び名]]` の手打ちが最大の負担だった |
| P4 | **未登録でも止めない**。新しい人や場所は名前だけで保存する | 未作成リンクのままでも日記は書かれていた |
| P5 | **主役は1日1ファイルの日記**（decisions #2） | 価値ある記録は日記の自由記述側に残っていた |
| P6 | **出力は Obsidian でそのまま読める Markdown**。既存のカレンダープラグイン・Dataview と互換にする | 振り返りは Obsidian で行う |

## 1. 日記ファイルのフォーマット

### 1.1 決定済み

- パス: `40_Diary/YYYY-MM-DD.md`（1日1ファイル）
- frontmatter の `type: diary`、`date`、`mood` は既存のまま（カレンダープラグインが使う）
- カレンダープラグインは「本文に文字がある、または `mood` がある」で「書いた」と判定し、最初の1行をプレビューに使う（`repository.ts` の `analyzeDiaryBody`）[確証]

### 1.2 選択肢: 出来事の書き方

**案A: 絵文字＋リンクの箇条書き（推奨）**

```markdown
---
type: diary
date: "2026-11-27"
mood: 😆
weather: ☁️
transaction: "-1419"
---

## 📝 今日の一言
- 風邪気味だったけど、最後はみんなで笑って楽しかった

## 🕒 できごと
- 12:10 ☀️ 📍[[場所A]] 👥[[姓 名|呼び名]] [[姓 名|呼び名]]
  みんなでゲームした。一人だけ強すぎた
  ![[attachments/photo-1795700000000.jpg]]
- 18:45 📍[[コンビニ]] 💴-429
  ホットドッグとピザまん
```

- 長所: Obsidian で一番読みやすい。リンクなので人物・場所ノートの**バックリンクに自動で出る**。Dataview も `file.outlinks` で拾える [一般知識]
- 短所: 金額を集計するには本文の解析が必要 → 1日の合計を frontmatter の `transaction` にアプリが書き込んで解決する（既存の符号付き文字列形式と同じ）

**案B: Dataview のインラインフィールド**

```markdown
- 18:45 ホットドッグとピザまん [place:: [[コンビニ]]] [spent:: 429]
```

- 長所: Dataview で出来事ごとに集計できる
- 短所: 読むとき `place::` が目に入ってうるさい。iPhone の Obsidian で手直しするときに書式を崩しやすい

**案C: 1出来事1見出し**

```markdown
### 18:45 コンビニ
- 👥 —
- 💴 -429
- ホットドッグとピザまん
```

- 長所: 出来事の区切りがはっきりする。アウトラインで一覧できる
- 短所: 行数が増える。1日に何件も書くと長い

### 1.3 frontmatter（案A の場合）

| キー | 内容 | 誰が書く |
|---|---|---|
| `type` | `diary` | アプリ（ファイル作成時） |
| `date` | `"YYYY-MM-DD"` | アプリ |
| `mood` | 絵文字1つ（その日の気分） | ユーザー（1タップ） |
| `weather` | その日最初の記録時点の天気の絵文字 | アプリ（自動） |
| `transaction` | その日の支出・収入の合計（`"-1419"` 形式） | アプリ（出来事の 💴 から再計算） |

人物・場所の一覧は frontmatter に持たない（本文のリンクから `file.outlinks` で取れるので二重管理になる）。

## 2. 入力項目の仕分け

| 項目 | 区分 | 方法 |
|---|---|---|
| 日付・時刻 | **自動** | 記録した時刻。あとから変更可（「19時半に行った」を夜に書く場合など） |
| 天気 | **自動** | 端末の位置情報 → Open-Meteo の現在の天気 → ☀️☁️☔️❄️ などの絵文字（旧データの絵文字に合わせる） |
| 本文（ひとこと） | 任意 | 1行でよい。iPhone の音声入力も使える |
| ムード | 任意（1タップ） | 😆😃🙂😐🙁 など5～6個から選ぶ。その日の `mood` に入る |
| 人物 | 任意（選ぶ） | 候補チップから選ぶ。呼び名（aliases）で表示し、書き出すときは `[[姓 名\|呼び名]]` に自動変換。最近よく会う人を先頭に |
| 場所 | 任意（選ぶ） | 候補から選ぶ。最近行った場所が先頭。検索は名前と aliases で |
| 金額 | 任意 | 数字キーパッド。支出と収入を切り替え |
| 写真 | 任意 | 撮影またはライブラリから選択。ブラウザ内で縮小（長辺500px、JPEG 0.85。mobile-photo-resizer の設定に合わせる）して `attachments/` にアップロード |
| カテゴリ（自分・家族・友人・学校） | **廃止** | 人物から推測できる。どうしても必要なら後で追加 |
| だれと・どこで・なにをのタグ | **廃止** | 人物・場所のリンクで代わりになる |

**保存できる最低条件**: 本文・写真・ムード・人物・場所・金額の**どれか1つ**があればよい（P1）。

### 新しい人・場所が出てきたとき（P4）

| 案 | 内容 |
|---|---|
| **案1（推奨）** | 名前を打つだけで保存。未作成リンク `[[新しい人]]` になる。アプリに「未登録の名前」一覧を出し、ノート作成は PC で気が向いたときに |
| 案2 | アプリがその場で `00_Inbox/` に最小限のノート（`type: person` / `type: place` と名前だけ）を作る |

## 3. 画面の流れ

### 3.1 選択肢: メイン画面のスタイル

| 案 | 内容 | 向いている使い方 |
|---|---|---|
| **案X: チャット型（推奨）** | 自分宛ての LINE のように、下の入力欄に打って送信 → その日のタイムラインに積み上がる。入力欄の上に 👥📍💴📷 のボタン | 1日に何度も短く書く |
| 案Y: タイムライン＋「＋」ボタン | 今日の出来事の一覧と、右下の「＋」。押すと入力シートが下から出る | 1日に数回、少し丁寧に書く |
| 案Z: 夜のふりかえりウィザード | 1日1回、質問に順に答える（気分 → 今日の写真 → 誰と・どこで → ひとこと） | 夜にまとめて書く |

案X と案Z は両立できる（日中はチャット型で書き、夜に「今日の一言とムード」だけ聞く画面を出す）。

### 3.2 画面一覧（案X の場合）

| 画面 | 内容 |
|---|---|
| 今日 | タイムライン（今日の出来事）＋入力欄。上部に日付・天気・ムード・連続日数 🔥 |
| 出来事の編集 | タップで本文・時刻・人物・場所・金額・写真を直す／削除 |
| 他の日 | 日付を左右に移動して過去の日記を見る・追記する |
| 人物・場所ピッカー | 検索欄＋最近の候補。未登録の名前もそのまま追加可 |
| 設定 | Dropbox ログイン・ログアウト、候補の再読み込み |

### 3.3 保存の仕組み（技術メモ）

1. 今日のファイルを取得（なければテンプレートから作る）
2. 「できごと」セクションの末尾に追記し、frontmatter の `transaction`・`weather`・`mood` を更新
3. `files/upload` を `mode: update` + 取得時の rev で書き込む。競合したら取り直して再追記（`spike-result.md` で検証済み）
4. オフラインや失敗のときは端末内に一時保存し、あとで再送

## 4. 続けるための仕掛け（候補）

| 案 | 内容 | 実現性 |
|---|---|---|
| 連続日数 🔥 | 今日の画面に表示（カレンダープラグインと同じ数え方） | 容易 |
| 1年前の今日 | 去年の同じ日の日記の1行目を表示 | 容易（データが溜まってから効く） |
| 毎晩のリマインド | iOS の「リマインダー」アプリか、ショートカットの「時刻」オートメーションで、毎晩 Dairys を開く | 容易（アプリ側の実装なし） |
| Web プッシュ通知 | ホーム画面に追加した Web アプリへの通知 | iOS 16.4 以降で可能だが、送信用サーバー（例: Cloudflare Workers）が必要 [一般知識]。MVP 対象外 |
| 写真から下書き | 今日撮った写真を選ぶと、撮影時刻で出来事の下書きを作る | iOS のファイル選択で撮影時刻・位置が取れるかは要検証 [推測] |

## 6. 既存資産との関係

| 対象 | 扱い |
|---|---|
| カレンダープラグイン | 日記の 📝・連続日数・プレビューはそのまま動く。日記内の `transaction` を月の集計に含めるには改修が必要（後回し） |
| 人物・場所ノート | アプリは**読むだけ**（候補表示用）。書き換えない |

| 日記テンプレート | 案A の「今日の一言」「できごと」の2セクション構成に合わせる |
