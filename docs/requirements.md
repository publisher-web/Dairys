# 要件定義（Step 2）— 案

状態: **ドラフト（2026-11-26、R1～R4 決定済み）**。「選択肢」の各項目は、ユーザーが選んだら「決定」に書き換え、`decisions.md` に記録する。

## 0. 設計の原則（分析からの結論）

| # | 原則 | 根拠（`analysis-current-state.md`） |
|---|---|---|
| P1 | **その場の入力は1画面・10秒以内**。必須項目は「何か1つ」だけ | 旧運用は1件に15～20操作＋YAML 7項目で途絶えた |
| P2 | **入口は1つ**。日記・出来事・支出を書き分けさせない | 入口が5系統に分かれていた |
| P3 | **手打ちさせない**。時刻・天気は自動、人物・場所は候補から選ぶ | `[[姓 名\|呼び名]]` の手打ちが最大の負担だった |
| P4 | **未登録でも止めない**。新しい人や場所は名前だけで保存する | 未作成リンクのままでも日記は書かれていた |
| P5 | **主役は1日1ファイルの日記**（decisions #2） | 価値ある記録は日記の自由記述側に残っていた |
| P6 | **出力は Obsidian でそのまま読める Markdown**。既存のカレンダープラグイン・Dataview と互換にする | 振り返りは Obsidian で行う |

## 1. 日記ファイルのフォーマット

### 1.1 決定済み

- パス: `40_Diary/YYYY-MM-DD.md`（1日1ファイル）
- frontmatter の `type: diary`、`date`、`mood` は既存のまま（カレンダープラグインが使う）
- カレンダープラグインは「本文に文字がある、または `mood` がある」で「書いた」と判定し、最初の1行をプレビューに使う（`repository.ts` の `analyzeDiaryBody`）[確証]

### 1.2 出来事の書き方 — **決定: 案A**（decisions #16）

**案A: 絵文字＋リンクの箇条書き（推奨）**

```markdown
---
type: diary
date: "2026-11-27"
mood: 😆
weather: ☁️
transaction: "-1419"
---

## 📝 今日の一言
- 風邪気味だったけど、最後はみんなで笑って楽しかった

## 🕒 できごと
- 12:10 ☀️ 📍[[場所A]] 👥[[姓 名|呼び名]] [[姓 名|呼び名]]
  みんなでゲームした。一人だけ強すぎた
  ![[attachments/photo-1795700000000.jpg]]
- 18:45 📍[[コンビニ]] 💴-429
  ホットドッグとピザまん
```

- 長所: Obsidian で一番読みやすい。リンクなので人物・場所ノートの**バックリンクに自動で出る**。Dataview も `file.outlinks` で拾える [一般知識]
- 短所: 金額を集計するには本文の解析が必要 → 1日の合計を frontmatter の `transaction` にアプリが書き込んで解決する（既存の符号付き文字列形式と同じ）

**案B: Dataview のインラインフィールド**

```markdown
- 18:45 ホットドッグとピザまん [place:: [[コンビニ]]] [spent:: 429]
```

- 長所: Dataview で出来事ごとに集計できる
- 短所: 読むとき `place::` が目に入ってうるさい。iPhone の Obsidian で手直しするときに書式を崩しやすい

**案C: 1出来事1見出し**

```markdown
### 18:45 コンビニ
- 👥 —
- 💴 -429
- ホットドッグとピザまん
```

- 長所: 出来事の区切りがはっきりする。アウトラインで一覧できる
- 短所: 行数が増える。1日に何件も書くと長い

### 1.3 frontmatter（案A の場合）

| キー | 内容 | 誰が書く |
|---|---|---|
| `type` | `diary` | アプリ（ファイル作成時） |
| `date` | `"YYYY-MM-DD"` | アプリ |
| `mood` | 絵文字1つ（その日の気分） | ユーザー（1タップ） |
| `weather` | その日最初の記録時点の天気の絵文字 | アプリ（自動） |
| `transaction` | その日の支出・収入の合計（`"-1419"` 形式） | アプリ（出来事の 💴 から再計算） |

人物・場所の一覧は frontmatter に持たない（本文のリンクから `file.outlinks` で取れるので二重管理になる）。

## 2. 入力項目の仕分け

| 項目 | 区分 | 方法 |
|---|---|---|
| 日付 | **自動** | 今日（切り替えで昨日・任意の日） |
| 出来事の時刻 | 任意 | 夜のふりかえりなので「だいたい」でよい。写真の撮影時刻が取れれば下書きに入れる |
| 天気 | **自動** | 端末の位置情報 → Open-Meteo の日単位・1時間ごとの天気（過去92日まで）→ ☀️☁️☔️❄️ などの絵文字（旧データに合わせる） |
| 本文（ひとこと） | 任意 | 1行でよい。iPhone の音声入力も使える |
| ムード | 任意（1タップ） | 😆😃🙂😐🙁 など5～6個から選ぶ。その日の `mood` に入る |
| 人物 | 任意（選ぶ） | 候補チップから選ぶ。呼び名（aliases）で表示し、書き出すときは `[[姓 名\|呼び名]]` に自動変換。最近よく会う人を先頭に |
| 場所 | 任意（選ぶ） | 候補から選ぶ。最近行った場所が先頭。検索は名前と aliases で |
| 金額 | 任意 | 数字キーパッド。支出と収入を切り替え |
| 写真 | 任意 | 撮影またはライブラリから選択。ブラウザ内で縮小（長辺500px、JPEG 0.85。mobile-photo-resizer の設定に合わせる）して `attachments/` にアップロード |
| カテゴリ（自分・家族・友人・学校） | **廃止** | 人物から推測できる。どうしても必要なら後で追加 |
| だれと・どこで・なにをのタグ | **廃止** | 人物・場所のリンクで代わりになる |

**保存できる最低条件**: 本文・写真・ムード・人物・場所・金額の**どれか1つ**があればよい（P1）。

## 3. 画面の流れ — **決定: 夜のふりかえり型（ウィザード）**（decisions #17）

比較した案（チャット型・タイムライン＋「＋」・夜のふりかえり）の中から、ユーザーが夜のふりかえり型を選んだ。

### 3.1 弱点と対策

| 弱点 | 対策 |
|---|---|
| その夜に開かないと0件になる | ①日付を「今日／昨日／任意の日」で切り替えて**あとから書ける**、②**毎晩のリマインド**（iOS のリマインダーかショートカットの時刻オートメーションで Dairys を開く。アプリ側の実装は不要） |
| 夜には昼の細部（時刻・金額）を忘れている | 時刻は「だいたい」でよい（任意入力）。金額も任意。写真の撮影時刻が取れたら下書きに使う |
| 途中で閉じると入力が消える | 入力途中の内容を端末内に自動で一時保存し、次に開いたときに続きから再開 |

### 3.2 ウィザードの流れ（案）

```
[0] 開始画面   11/27(金) の日記を書く  🔥3日   〔日付を変える〕
     ↓
[1] 気分       今日はどんな日だった？  😆 😃 🙂 😐 🙁（タップで次へ）
     ↓
[2] できごと   今日あったことを追加（0件でも次へ進める）
               ┌ カード ─────────────────────┐
               │ 🕒 12:10   📍Link Lab  👥呼び名… │
               │ 💴 -429   📷[写真]              │
               │ ひとこと: みんなでゲームした     │
               └─────────────────────────────┘
               〔＋できごとを追加〕〔📷写真から追加〕
     ↓
[3] 今日の一言  1日をひとことで（音声入力も可）
     ↓
[4] 確認・保存  Obsidian でどう見えるかのプレビュー → 〔保存〕
```

- 天気は自動: その日の天気（日単位）を frontmatter の `weather` に、出来事の時刻があれば**その時刻の天気**を出来事の行に入れる（Open-Meteo の過去92日分の1時間ごとのデータ [確証]）
- 「📷写真から追加」: 写真を複数選ぶと、1枚（または近い時刻の数枚）ごとにカードを作る。撮影時刻が取れればカードの時刻に入れる（iOS で撮影日時が残るかはバージョンにより不安定 [確証: WebKit バグ報告]。取れなければ空欄）
- どのステップも「スキップ」できる。保存できる最低条件は「何か1つ入っている」こと（P1）
- その日の日記がすでにある場合は読み込み、気分・一言は上書き、できごとは追加・編集できる

### 3.3 画面一覧

| 画面 | 内容 |
|---|---|
| 開始 | 対象の日付、連続日数 🔥、その日の記入状況（未記入／記入済み） |
| ウィザード [1]～[4] | 上記 |
| 人物・場所ピッカー | 検索欄（名前・読み・aliases）＋最近の候補。未登録の名前もそのまま追加できる |
| 未登録の名前 | 未作成リンクになっている人・場所の一覧（ノート作成は PC で） |
| 設定 | Dropbox ログイン・ログアウト、候補の再読み込み |

### 3.4 保存の仕組み（技術メモ）

1. 対象日のファイルを取得（なければテンプレートから作る）
2. frontmatter の `mood`・`weather`・`transaction` を更新、「今日の一言」を書き換え、「できごと」を時刻順に並べて書き出す
3. `files/upload` を `mode: update` + 取得時の rev で書き込む。競合したら（Obsidian 側で同じ日を編集していた等）取り直して、アプリの変更だけを当て直す
4. 写真は先に `attachments/photo-<タイムスタンプ>.jpg` へアップロードし、成功したものだけリンクする
5. 通信できないときは端末内に保存し、次回に再送

## 4. 続けるための仕掛け（候補）

| 案 | 内容 | 実現性 |
|---|---|---|
| 連続日数 🔥 | 開始画面に表示（カレンダープラグインと同じ数え方: 今日が未記入なら昨日から数える） | 容易 |
| 書き忘れの表示 | 開始画面に「昨日がまだです」と出して、ワンタップで昨日を書ける | 容易 |
| 1年前の今日 | 去年の同じ日の日記の1行目を表示 | 容易（データが溜まってから効く） |
| 毎晩のリマインド | iOS のリマインダーまたはショートカットの時刻オートメーション | アプリ側の実装なし |
| Web プッシュ通知 | ホーム画面に追加した Web アプリへの通知 | 送信用サーバー（例: Cloudflare Workers）が必要 [一般知識]。MVP 対象外 |
