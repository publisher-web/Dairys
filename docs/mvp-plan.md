# Step 3 MVP 実装計画

状態: **承認済み（2026-11-26）・M1/M2 完了、デザイン刷新中**。マイルストーンごとに「実装 → ビルド・テスト → push → 報告して停止」で進める。

要件は `requirements.md`（確定版）を正とする。

## 方針

| 項目 | 方針 | 理由 |
|---|---|---|
| 画面遷移 | ルーターは使わず、ウィザードの状態（どのステップか）を React の state で管理 | 画面数が少なく、GitHub Pages ではルーターの URL 設定が手間 [一般知識] |
| 日記の読み書き | 「frontmatter」「今日の一言」「できごと」だけをアプリが管理し、**それ以外の本文は一字一句そのまま残す** | Obsidian で手で書いた内容を壊さないため（最重要） |
| テスト | 日記のパース・書き出し、金額の合計、連続日数など**ロジック部分は Vitest で自動テスト** | 壊れると日記が消えるので、ここだけは確実にしたい |
| 端末内保存 | 入力途中の内容と未送信データは IndexedDB に保存（写真のような大きいデータも扱える） | localStorage は容量が小さい [一般知識] |
| 依存ライブラリ | 最小限。追加は Vitest と、必要なら EXIF 読み取り用の小さなライブラリだけ | 保守を楽にするため |
| コード規約 | コード内コメントなし（ユーザールール） | — |

## 主なリスク

| リスク | 対策 |
|---|---|
| Obsidian 側で同じ日の日記を編集していて競合する | rev による楽観ロックで検出し、取り直してからアプリの変更だけを当て直す（Step 1 で検証済み） |
| 既存の日記の書式（旧形式の「今日の一言」だけのもの）を壊す | M1 で実際の日記3件をテストデータにする（Public なので中身は伏せたダミーに置き換える） |
| iOS で写真の撮影時刻が取れない | 取れなければ時刻は空欄。手入力で補う |
| 位置情報の許可を拒否された | 天気は空欄で保存（必須にしない） |
| Remotely Save の同期前に Obsidian で同じ日を編集 | Remotely Save の競合処理（新しい方を残す）に任せる。運用で「当日分はアプリから書く」を推奨 |

## 進捗メモ

### M1（2026-11-26 完了）

- `src/diary/markdown.ts`: 日記のパース・書き出し。アプリが触るのは frontmatter の `type`/`date`/`mood`/`weather`/`transaction` と「今日の一言」「できごと」の2セクションだけ。未変更の出来事は元の行（`raw`）をそのまま書き戻す
- `src/dropbox/guard.ts`: 書き込みを `<Vault>/40_Diary/*.md` と `<Vault>/attachments/*.(jpg|png|webp)` に限定（`_`・`.` で始まる名前、`..`、`//` は拒否）。すべての書き込みは `writeVaultFile` を通す
- `src/storage/kv.ts`: IndexedDB の簡易 KV（下書き・未送信データ用。M2 以降で使う）
- 画面: ログイン・ホーム（M2 の準備表示＋保管庫の接続状態）・設定（保管庫の再検出・ログアウト・技術検証ページ）
- テスト: `npm test`（Vitest、44件）。CI でもビルド前に実行。実データでの往復テストは `src/diary/vault.local.test.ts`（gitignore 済み、PC の Vault がある場合のみ動く）
- 既知の挙動: ファイル末尾に新しいセクションを足すと、元の末尾改行が付かないことがある（Obsidian の表示には影響なし）

### M2（2026-11-27 完了）

- ホーム: 日付切替（昨日・今日・任意の日、`?date=YYYY-MM-DD` でも指定可）、連続日数、「昨日がまだ」バナー、記入状況（直近400日分を rev 付きでキャッシュ）
- ウィザード: できごと → 気分 → 今日の一言 → 確認・保存。気分を選ぶと自動で次へ
- 下書き: IndexedDB に自動保存（400ms 間隔）。再開時、下書き作成後に Obsidian 側で増えたできごとを合流
- 保存: rev 付き更新。競合したら最新を取り直し、Obsidian 側で増えたできごとを残して当て直す（最大4回）
- 動作確認（PC の Edge、テスト用の日付 2001-01-01）: 新規作成・既存への書き足し・時刻順の並べ替え・Obsidian への同期 OK
- 既知の制約: Obsidian 側で**既存の**できごとを編集し、同じ日をアプリでも編集して保存すると、アプリ側の内容で上書きされる（追加分は残る）
