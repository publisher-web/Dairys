## 発見した問題

| # | 問題 |
|---|---|
| 1 | 入口が5系統（イベント／買い物／収入／日記／Daily）あり、どこに書くか毎回判断が必要 |
| 2 | 日記とイベントに同じ出来事を二重に書いている日がある |
| 3 | 支出がイベントの `transaction`・Shopping・日記本文の3か所に分散 |

| 7 | 日記内の人物リンクに未作成のものがある（新規登録は後回しにされる） |
| 8 | Daily テンプレートと一部の場所ノートの Dataview が旧キー（`参加者`／`場所`／`開始`／`カテゴリ`）を使っていて、結果が常に空 |
| 9 | 未作成リンクから作られた場所ノートが Vault 直下にあり、テンプレートのダミー値が残っている |

| 11 | 時間がツール作り（プラグイン開発）に向き、その間に記録が止まっている [推測] |

## 日記（自由記述）の特徴

- 1日分に5～6件の出来事を箇条書きでまとめて書いている
- 人物は本文中に `[[姓 名|呼び名]]` とインラインでリンクしている
- 感情や感想が多く含まれていて、振り返ったときの価値が高い
- 同じ日の出来事（放課後の活動など）がイベントノートとしては作られていなかった → 1件ずつファイルを作る手間を避けている [推測]

## 設計への示唆

- 主役は「1日1ファイルの日記」とし、出来事はその中に追記する
- 人物・場所は本文中のリンクとして扱い、入力時は候補から選ぶ。未登録なら名前だけで保存してよい
- 天気・時刻は自動で入れ、ムードは1タップ
- 支出は出来事に金額を添えるだけにし、集計は後処理で行う
- tags（だれと／どこで／なにを）は入力させない（人物・場所から生成できる）
